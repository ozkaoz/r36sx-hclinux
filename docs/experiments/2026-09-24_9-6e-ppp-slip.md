# Experimento 9-6e-PPP: networking por serial (PPP/SLIP sobre CDC-ACM) — REFUTADO

**Fecha:** 2026-09-24 (noche)
**Clase de cambio:** C (kernel config) + E (rootfs) + stack (fork TreeFrogUI)
**Hipótesis:** el overlay azul del AVP lo dispara el *gadget* de red
(netdev/u_ether en el bus USB), no el networking en sí → un serial CDC-ACM
(clase modem, probada SIN azul) con PPP encima daría networking SIN overlay.

## Test físico (2026-09-24, usuario)

Flag `net.mode` en la SD (sin `ncm.mode` → default PPP). Evidencia cosechada de la SD:

- `NET_MODE_DEBUG.log` (sesión PPP): gadget ACM creado → role `b_idle`→`peripheral`
  → UDC bound → `/dev/ttyGS0` ready → `telnetd OK` → `pppd started pid=1353` —
  todo el lado consola OK. B exit 00:01:52 → "saliendo" (sin línea
  `restore done` registrada — flush/apagado la cortó; la sesión NCM previa sí
  registró `restore done rc=0`).
- `PPP_DEBUG.log`: pppd envía `LCP ConfReq` ×10 sobre ttyGS0 →
  **`LCP: timeout sending Config-Requests`** → reintento (channel 2) ×10 → igual
  → `Connection terminated`. **El PC nunca respondió** (el dial-up de Windows no
  llegó a configurarse).
- **Resultado visual (usuario): el overlay azul apareció IGUAL durante la sesión PPP.**

## Veredicto: HIPÓTESIS REFUTADA

1. La sesión PPP **sin conexión establecida** (LCP sin respuesta del PC)
   **disparó el azul** → el disparador NO es el descriptor del gadget network
   (un CDC-ACM no cambia su descriptor USB) ni el tráfico de red establecido.
2. Corrección de la conclusión de `2026-09-24_usb-networking-blue-overlay.md`:
   el azul correlaciona con **networking activo** (gadget CDC-network **o** pppd
   sobre ACM). El serial ACM puro (shell interactivo, sin pppd) NO lo dispara.
3. Matiz metodológico: del log solo no se puede excluir una contaminación
   stateful de la sesión NCM previa del mismo día (el overlay persiste tras B);
   la observación en vivo del usuario manda como evidencia (EVIDENCE > MEMORY).
4. Quedan agotadas las vías del lado kernel/DTS/transporte:
   DTS `usb0 disabled` (v15) ✗ · subclase CDC ✗ · serial-ACM networking ✗.
   El overlay es comportamiento intrínseco del firmware AVP de fábrica
   (`avp.uImage` `a9788995` == golden, intacto).

## Decisión (ADR-015)

- **NCM = transporte de red de PRODUCCIÓN** (adaptador nativo Windows +
  telnet root; networking PHYSICAL PASS por debajo del azul).
- Overlay azul = **limitación aceptada, display-only** (kernel/red/shell vivos
  debajo; capa residual tras B hasta reboot).
- `net_ppp.sh` + PPP/SLIP del kernel + pppd del rootfs: **retenidos como
  experimentales** (el kernel desplegado `e07844bd` los incluye; inofensivos
  sin uso).
- Eliminar el azul solo vía **firmware AVP propio** (workspace
  `~/work/r36sx-hclinux/avp-build/`) — clase D, aparcado PARA DESPUÉS,
  requiere autorización hardware.
